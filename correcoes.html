O que foi corrigido, arquivo por arquivo

Em ordem de quantos pontos cada problema podia custar. A arquivo novo, M modificado, D removido.

1. make test travava

Funcionamento + Testes · até −5

Cinco testes chamavam InterfaceJogo::solicitarEscolha ou Combate::iniciar, que leem std::cin. Com terminal, o make test parava esperando alguém digitar. Sem terminal (EOF), solicitarEscolha fazia cin.clear() e tentava de novo para sempre, a 80% de CPU. O enunciado diz que a correção usa a saída do make test.

  • Atests/EntradaSimulada.hppAjudante de teste (RAII): troca o buffer do std::cin por um texto fixo enquanto o objeto existe e devolve o teclado no destrutor.
  • Mtests/test_Combate.cppOs 3 testes de combate agora recebem 500 linhas “1” (ataque básico). Novo teste: EOF no meio do combate sobe como exceção em vez de ser engolido.
  • Mtests/test_InterfaceJogo.cppOs 2 testes “Stub” viraram testes de verdade: opção válida, número fora do intervalo, texto não numérico, EOF, lista vazia e pausar() sem entrada.
  • Ainclude/EntradaEncerradaException.hppExceção própria para “a entrada acabou”.
  • Msrc/InterfaceJogo.cppSe std::cin.eof(), lança EntradaEncerradaException em vez de repetir para sempre.
  • Msrc/Combate.cppO catch (std::exception&) do turno engolia tudo. Agora EntradaEncerradaException é relançada antes dele.
  • Msrc/main.cppTrata EntradaEncerradaException à parte: mostra “Entrada encerrada. Até a próxima!” e sai com código 0.

2. Arquivos com várias classes

Boas práticas OO · −2

O critério diz “deve ter somente uma” classe por arquivo. InimigoComum.hpp e InimigoIncomum.hpp tinham 3 classes cada; outros headers misturavam a classe com exceções e structs. A separação foi feita por script, sem mudar nenhuma linha de lógica.

  • Ainclude/ e src/ DesafianteDoBar, TrabalhadorNoturno, SegurancaDeBalada (.hpp + .cpp)Um par de arquivos por inimigo comum.
  • Ainclude/ e src/ RecrutaDoutrinado, GuardaPatrimonial, SabotadorRival (.hpp + .cpp)Um par de arquivos por inimigo incomum.
  • Minclude/InimigoComum.hpp · include/InimigoIncomum.hppViraram atalhos que só fazem #include dos 3 inimigos. Não declaram classe, então MotorJogo e os testes continuam funcionando sem mudança.
  • Dsrc/InimigoComum.cpp · src/InimigoIncomum.cppO conteúdo foi para os 6 .cpp novos.
  • Ainclude/CombateInvalidoException.hpp · include/HabilidadeInvalidaException.hppSaíram de Combate.hpp e Habilidade.hpp.
  • Ainclude/Escolha.hpp · include/EfeitoPorTempo.hpp · include/ModificadorAtributo.hppStructs que estavam em Cena.hpp e Personagem.hpp.
  • Minclude/Combate.hpp · include/Habilidade.hpp · include/Cena.hpp · include/Personagem.hppPassam a incluir os headers novos em vez de declarar os tipos.
  • Minclude/Inimigo.hpp · src/Inimigo.cpp · src/InimigoBoss.cppA função validarNivel estava copiada em 3 arquivos (num namespace anônimo). Virou um método protected static de Inimigo, usado pelos 7 inimigos. Também saíram dois métodos comentados e um bloco Doxygen quebrado (/** *//**).

3. Doxygen não documentava nada

Documentação · −1 a −2

O Doxyfile estava no padrão de fábrica: INPUT vazio e RECURSIVE = NO. Como não há código na raiz, o Doxygen não lia nenhum header. Além disso, quase nenhum método tinha @return, e havia uma sobra de conflito de merge dentro de um comentário.

  • MDoxyfileAgora lê README.md include src (recursivo), ignora o doctest.h, usa o README como página inicial, sai em português em doc/html e não gera LaTeX.
  • Minclude/Habilidade.hppTinha <<<<<<< HEAD / ======= / >>>>>>> 4c10a33 no comentário da classe. Ficou a versão mais nova. Os getters ganharam @return.
  • Minclude/Personagem.hpp · include/Aventureiro.hpp · include/InimigoBoss.hpp · headers dos 6 inimigos@return em todo método que devolve valor, @param forca que faltava no construtor e documentação de _modificadoresAtivos.
  • MMakefileNovo alvo make docs, que roda o Doxygen.

4. Arquivos de build versionados

Risco na correção

23 arquivos de build/ estavam no git, incluindo o executável jogo e dados de cobertura (.gcda/.gcno) antigos. O corretor pode acabar lendo cobertura velha.

  • M.gitignoreIgnora build/, *.gcno, *.gcda e *.gcov.
  • Dbuild/ (23 arquivos)Removidos da cópia. No repositório real, falta rodar git rm -r --cached build e commitar.

Como conferir

Dentro de repo-corrigido/:

make clean && make test   # 88 testes + resumo de cobertura
make run                  # joga
make docs                 # gera doc/html/index.html

A documentação já está gerada em repo-corrigido/doc/html/index.html. As saídas completas do make test no Linux e no macOS estão em evidencias/, e o diff de tudo em mudancas.diff.

O que ficou com o grupo

Não dava para resolver isto sem informação que só vocês têm, ou que é decisão de vocês.

  1. Preencher os arquivos de matrícula. Os 5 arquivos 20250xxxxx.txt dizem que só contam commits “de acordo com os dados de usuário cadastrados acima”, mas nenhum tem dados acima. Coloquem nome, usuário do GitHub e e-mail. A nota individual depende disso.

Há commits do mesmo aluno com nomes diferentes: Davi Costa/davicostaaa, Kaio Gomes Vieira/szkaio, Joao Pedro Guimaraes Carvalho/João Pedro Guimarães Carvalho/jpgcarvalho9876. Listem todas as identidades no .txt e configurem git config user.name e user.email iguais em todas as máquinas.
  3. Aplicar as correções em commits pequenos, um por problema acima, cada um feito por um aluno diferente. Isso divide a autoria e deixa o histórico legível para o corretor.
  4. Rodar uma vez em Linux antes de entregar: make clean && make test. Foi assim que os números acima foram medidos.

Conselhos para subir a nota e o código

  1. Cobertura de branches está em 43%. A de linhas passa folgado, mas a IA dos inimigos depende de rand(). Recebam o gerador como parâmetro, ou chamem srand com semente fixa nos testes, para cobrir os dois lados de cada decisão.
  2. Aventureiro.cpp (63%) e MotorJogo.cpp (73%) são os menos cobertos. Com o EntradaSimulada dá para testar o menu de habilidades, o escudo e o frasco de cura do Aventureiro, e o laço de cenas do MotorJogo::rodar().
  3. validarNivel nunca lança. O construtor de Personagem já rejeita nivel <= 0 antes, então o throw de Inimigo::validarNivel é código morto (as linhas 22–23 de Inimigo.cpp aparecem sem cobertura por isso). Escolham um dos dois lugares para validar.
  4. Cartão CRC de Combate só lista ações. O critério pede responsabilidades de conhecimento (atributos) e de realização (métodos). Acrescentem algo como “conhece o turno atual” e “conhece os dois combatentes”.
  5. Escolher um template de PR. Há .github/pr_template.md e .github/PULL_REQUEST_TEMPLATE.md; o GitHub só usa o segundo.
  6. Juntar as notas de design. notas.md, notas-C6.md e notas-C7.md têm de 4 a 9 linhas cada. Um arquivo só, ou nada.
  7. .vscode/ é configuração local de editor. Coloquem no .gitignore.
  8. A main ainda diz “INICIANDO AMBIENTE DE TESTE NA MAIN” e o herói se chama Aragorn. Para a entrega, troquem por uma abertura do jogo.

Não foi mudada nenhuma regra de jogo, nenhum valor de balanceamento e nenhum texto da história. Toda mudança é de estrutura, testes, tratamento de entrada ou documentação.
